SSystemic structure

ExampleApp holds 46% of the code in one target

OpenRoot cost 1 · Affected 0/65Risk 18.26%

Describe the problem

ExampleApp’s feature folders construct each other’s types directly, so the app is one indivisible unit.

Why it’s a problem

Any Sharing change recompiles and revalidates Library and Editor code, and no folder can move out without untangling the rest.

How to fix it

Move Library into its own target and replace direct SharingSession construction with an injected DocumentSharing contract.

Why it’s a problem

How to fix it
